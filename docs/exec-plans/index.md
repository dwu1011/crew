# Execution plans

Use [active](active/index.md) for substantial work in progress and [completed](completed/index.md) for finished plans and their evidence. Track follow-up work in [technical debt](tech-debt.md).

## Plan contents

Each substantial plan needs a status, goal, scope and non-goals, dependencies, implementation steps, observable acceptance criteria, verification commands and results, decision log, and remaining questions.

Update progress during work. Link to product specs and designs instead of repeating them. Move a plan to completed only after its acceptance criteria are met; retain failed checks, unresolved limitations, and the distinction between automated evidence and human sign-off.

Small changes can use lightweight task notes instead of a full plan. Preserve existing historical tickets in place and link them from the completed index.
